# 🌐 Pool Villa & Home Lab Network Architecture Documentation

เอกสารฉบับนี้จัดทำขึ้นเพื่ออธิบายโครงสร้างระบบเครือข่ายรูปแบบ Hybrid Network (Pseudo-Bridge Mode via DMZ) สำหรับธุรกิจ Pool Villa และพื้นที่พัฒนาระบบ Home Lab ส่วนตัว เพื่อเป็นคู่มือในการดูแลรักษาระบบและการตั้งค่าในอนาคต

## 📊 2. ตารางการจัดสรรพอร์ตและ IP (IP Address Allocation)

- Huawei Main (AIS) [วงนอกสุด / Gateway 1]
  * IP Address: 192.168.1.1
  * คำอธิบาย: ตัวรับสัญญาณไฟเบอร์หลัก ทำ NAT ชั้นที่ 1 และจัดการ DMZ

- Huawei Sub (AIS) [วงนอกสุด / Client]
  * IP Address: 192.168.1.X (รับจากตัวหลัก)
  * คำอธิบาย: รับสัญญาณผ่านสาย FTTR กระจาย Wi-Fi ให้ลูกค้า Pool Villa

- Hikvision NVR [วงนอกสุด / CCTV]
  * IP Address: 192.168.1.100 (Static)
  * คำอธิบาย: ต่อสาย LAN เข้า Huawei ดูภาพผ่านระบบ Hik-Connect Cloud P2P ได้ปกติ

- Omada ER605 (ขา WAN)
  * IP Address: 192.168.1.200 (Static)
  * คำอธิบาย: รับสาย LAN จากพอร์ต LAN ของ Huawei เข้าช่อง WAN พอร์ต 1 เพื่อรอรับทราฟฟิกจาก DMZ

- Omada ER605 (ขา LAN) [วงในสุด / Gateway 2]
  * IP Address: 192.168.50.1
  * คำอธิบาย: ประตูหลักของวงแลนโซนเซิร์ฟเวอร์ คุมแจก IP วงในแยกขาดจากวง AIS

- Raspberry Pi 4 [โซนระบบภายใน]
  * IP Address: 192.168.50.2 (Fixed IP via DHCP Reservation)
  * คำอธิบาย: รัน Omada Controller และเป็นจุดจบสายของท่อ WireGuard VPN

- Intel NUC [โซนระบบภายใน]
  * IP Address: 192.168.50.X
  * คำอธิบาย: รันระบบ Automation / Services โฮมแล็บหลังบ้าน

⚠️ ข้อควรระวังเรื่อง DHCP Range:
วง LAN ของ ER605 ตั้งค่าแจก DHCP Range ตั้งแต่ 192.168.50.10 ถึง 192.168.50.254 เพื่อเว้นช่องว่างช่วงต้น (.2 ถึง .9) ไว้สำหรับทำ Fixed IPให้อุปกรณ์สำคัญ เพื่อป้องกันการเกิด IP ชนกันในระบบ

## 🔄 3. กลไกการเดินทางของข้อมูล (Traffic Flow)

3.1 การใช้งานอินเทอร์เน็ตของลูกค้า (ขากลับส่งถูกเครื่องได้อย่างไร?)
เมื่อลูกค้าฝั่ง Wi-Fi AIS เปิดเว็บ ข้อมูลวิ่งกลับมาถูกเครื่องไม่ปนกับฝั่งเซิร์ฟเวอร์ แม้จะเปิด DMZ ไว้ก็ตาม เนื่องจาก:
1. NAT Table / Session Tracking: เมื่อลูกค้าส่งคำขอออกไป เราเตอร์ Huawei AIS จะเปิดสมุดจดบันทึกพิกัดไว้ล่วงหน้าว่าเครื่องไหนเป็นคนขอข้อมูลชิ้นไหน
2. เมื่อข้อมูลจากอินเทอร์เน็ตส่งกลับมา Huawei จะเปิดสมุดตรวจเช็คก่อนเป็นอันดับแรก หากพบว่าเป็นทราฟฟิกที่ลูกค้าสั่งไว้ มันจะส่งตรงไปให้ลูกค้าเครื่องนั้นทันที โดยไม่ผ่านกฎ DMZ
3. ฟังก์ชัน DMZ จะทำงานต่อเมื่อมี ทราฟฟิกแปลกหน้า (Unsolicited Inbound) ยิงตรงเข้ามาจากภายนอกโดยไม่มีเครื่องไหนในบ้านร้องขอมาก่อน (เช่น ทราฟฟิก VPN ขากลับของคุณ) มันถึงจะถีบส่งข้อมูลนั้นไปให้ ER605 (192.168.1.200) จัดการต่อ

3.2 การข้ามวง NAT ระหว่างโซนภายใน และ โซนภายนอก (One-Way NAT)
- จากฝั่งเซิร์ฟเวอร์ วิ่งไปหากล้องวงจรปิด (วงใน -> วงนอก): "ทำได้โดยตรง" เพราะ NAT บน ER605 อนุญาตให้ทราฟฟิกขาออกวิ่งผ่านได้อย่างอิสระ คอมพิวเตอร์หรือเครื่อง NUC หลัง ER605 จึงสามารถดึงภาพสดจากกล่อง Hikvision วงนอกผ่าน IP 192.168.1.100 มามอนิเตอร์ได้ทันที
- จากฝั่งลูกค้า วิ่งเข้ามาหาเซิร์ฟเวอร์ (วงนอก -> วงใน): "โดนบล็อก 100%" เนื่องจาก ER605 ทำหน้าที่เป็น Firewall ขวางไว้ ทำให้ลูกค้าพูลวิลล่าไม่มีสิทธิ์มองเห็นหรือเจาะระบบเข้ามายัง Intel NUC หรือ Raspberry Pi ได้ ปลอดภัยอย่างสมบูรณ์

## 🔒 4. การจัดการระบบรีโมทระยะไกล (WireGuard VPN)

เนื่องจากระบบติดปัญหาเน็ตซ้อน (Double NAT) การรีโมทจากนอกบ้านมาคุมโฮมแล็บจึงเสร็จสมบูรณ์ได้ด้วยการผสานเทคโนโลยี DMZ + WireGuard VPN + Cloudflare DDNS (รัน updater บน Raspberry Pi คอยอัปเดต public IP ของ AIS เข้า DNS record)

4.1 การตั้งค่าฝั่ง Server (Omada Controller)
- รันอยู่บนพอร์ตฟังคำขอ (Listen Port) 51820
- จ่ายวง IP จำลอง (Tunnel Network) เป็นวง 10.0.0.1/24
- มีการผูกคีย์สาธารณะ (Public Key) ของแต่ละอุปกรณ์ไว้ในแท็บ Peer เช่น เครื่องคอมพิวเตอร์ลินุกซ์ส่วนตัว (Porschubuntu) ที่ล็อก IP ในท่อไว้เป็น 10.0.0.2/32

4.2 การตั้งค่าฝั่ง Client (Linux / Porschubuntu)
ใช้คีย์เข้ารหัสแบบ Base64 (ความยาว 44 ตัวอักษร ลงท้ายด้วย =) วิ่งมุดเข้าอุโมงค์ผ่านไฟล์คอนฟิก /etc/wireguard/wg0.conf โดยระบุ Endpoint ชี้มายังชื่อโดเมนที่ใช้ Cloudflare DDNS (อัปเดต A-record อัตโนมัติผ่าน Cloudflare API จาก Raspberry Pi) พ่วงด้วยพอร์ต 51820 

เมื่อสั่งรัน "sudo wg-quick up wg0" ระบบจะเจาะทะลุผ่านเราเตอร์ AIS เข้ามาเชื่อมต่อกับวงภายใน 192.168.50.0/24 เสมือนยกเครื่องคอมพิวเตอร์ส่วนตัวมานั่งเสียบสายแลนอยู่ในห้องทำงานพูลวิลล่าทันที

## ⚠️ 5. ข้อจำกัดและสิ่งที่จะต้องพัฒนาต่อในอนาคต (Next Steps)

1. การพิสูจน์ตัวตนของลูกค้า (Captive Portal): ในเฟสแรกนี้ ลูกค้ายังเกาะ Wi-Fi คอนโทรลเลอร์ของค่าย AIS ตรงๆ จึงยังไม่สามารถทำระบบแจกตั๋วล็อกอิน (Voucher) ได้ ลูกค้าจะเข้าใช้งานด้วยรหัสผ่าน Wi-Fi กลางตามปกติ
2. การขยายระบบ (Phase 2): เมื่อธุรกิจนิ่งและพร้อมลงทุนเพิ่ม สามารถจัดหา Omada Access Point (AP) มาต่อหลัง ER605 เพื่อกระจายสัญญาณ Wi-Fi โซนลูกค้าแยกเป็นอีกวงหนึ่ง (Multi-SSID VLAN) เพื่อดึงสิทธิ์การคุมระบบตั๋วและเก็บ Log พ.ร.บ. คอมพิวเตอร์ กลับมาบริหารจัดการที่ Raspberry Pi ได้อย่างสมบูรณ์แบบ
